# Hazel and Forel compatibility

This is a support matrix for Forel's current native features and Hazel import, not a claim of complete Hazel parity. Native controls can support a feature whose Hazel archive encoding is not yet verified. Unsupported or unrecognized imported rule parts are reported and block execution rather than being discarded. Hazel-imported rules are disabled for review. The pinned-corpus audit covers 33 exports and 55 rules; it does not cover every Hazel version or encoding. See [the runtime scenario inventory](HAZEL-RUNTIME-COVERAGE.md) for which original rules were exercised and where tests substituted scripts, metadata, clocks or host services.

## Rules and conditions

| Family | Native support | Boundaries and import behavior |
| --- | --- | --- |
| Rule logic | All, any and none; nested groups; current item, parent, any/all children or siblings; folder depth and recursive traversal. | Groups, recursion and evaluation work are bounded. Missing or unreadable values remain unknown, including under negation. Unsupported archive targets or operators are blocked. |
| Ordering and control | Native rules can opt into **Use Hazel rule ordering**. Matching Hazel-ordered rules stop later rules unless they explicitly continue; a recurse action evaluates folder contents. | The toggle is required for native Hazel Continue and Run Rules on Folder Contents actions. Without it, ordinary native rule ordering applies. |
| File properties | Name and full filename, extension, kind/content type, size, subfolder depth and child count; lock state, Finder tags, color labels and comment; download source and originating app. | Availability depends on filesystem and macOS metadata. Imported `hazelkind:` descriptions use the host's exact Finder type description. Unavailable metadata fails closed. |
| Dates and times | Created, modified, added, last opened and last matched; comparisons against other built-in or custom dates, fixed dates, relative durations, today/yesterday/tomorrow, week/month/year and local-time recurrence. | Scheduled rechecks and persisted match state handle supported time-sensitive rules. Missing Spotlight last-opened data and unavailable custom dates do not become matches through negation. Only evidenced Hazel date/recurrence encodings are imported. |
| Spotlight | Editable typed text, number, Boolean, date and list comparisons; typed action tokens. | Spotlight indexing and metadata availability are host dependent. Native action tokens freeze referenced metadata before actions. Unknown Hazel Spotlight archive encodings are blocked. |
| Custom values | Editable named regex text and date captures, lists collected from contents or Finder tags, and inline or file-backed delimited list/table matches. Subsequent conditions and actions can use captured values and table columns. Script outputs can also supply typed values. | Later match-defined captures must agree with previously bound values. File-backed tables use UTF-8, a one-character separator and bounded reads; full Hazel pattern-defined list/table/date grammar and unverified archive encodings remain unsupported. |
| Content | Plain text, PDF, RTF, Office, OpenDocument, iWork previews and supported images; automatic, disabled or forced OCR; a separate PDF password condition. | Extraction differs from Hazel/Spotlight and depends on host services. Unsupported formats may have a Spotlight `contains` fallback only. Failed, locked or partial extraction is unknown rather than a negative match. |
| Scripts | Shell, AppleScript and JavaScript condition scripts, with named input/output attributes where supported. | Condition scripts **run during Dry Run**, and may have side effects; action scripts do not run during preview. Scripts require their interpreter, permissions and any referenced programs. Only verified embedded/external/compiled Hazel forms are imported. |
| Peer ranking | Native top-N size or created, modified, added or last-opened date ranking among visible same-folder peers, with editable peer filters; other safe ALL conditions also narrow peers. | Ties use deterministic filename order; Hazel's tie behavior is unverified. Content/OCR, scripts, change tracking and context-dependent filters are rejected; unavailable peer data fails closed. Multiple rankings in one group and unverified Hazel ranking encodings are blocked. A peer-only recheck stops at an earlier script or continuing Hazel rule with actions and records why, rather than replaying them. |
| Change tracking | Native did-change/did-not-change for names, extensions, Finder comments, sizes and created/modified/added dates, including nested groups. | An actual first observation seeds a per-rule, per-condition baseline; Dry Run does not. A changed value remains pending after failed actions. This scope differs from Hazel's observed file-level attribute cache. Other attributes and unverified Hazel archive encodings are blocked. |

## Actions and execution

| Family | Native support | Boundaries and import behavior |
| --- | --- | --- |
| File operations | Move, copy, sync, rename, Trash and delete; conflict handling, duplicate handling and supported source-folder structure options. | Destination permissions and filesystem behavior apply. Symlink/path safety, conflict and replacement checks can reject an operation. Unsupported Hazel option values are blocked. Sync can remove destination items absent from the source. |
| Finder metadata | Add/remove tags, color label, Finder comment, lock and extension visibility; dynamic patterns, including expanding a captured list into separate tags. | Finder and filesystem metadata availability varies. Multiple simultaneously expanded lists are rejected. Unverified dynamic-tag archive variants are blocked. |
| Applications and workflows | Open with default or selected app, show in Finder, create alias, notifications, Shortcuts, library import and Automator workflow. | Apps, automation permissions, format support and host services are required. Automator receives the matched file; its host timeout may not cancel an already-running workflow. Unsupported or unverified Hazel workflow encodings are blocked. |
| Scripts | Shell scripts, AppleScript and JavaScript actions; verified legacy and modern Hazel forms. | These can run arbitrary programs and require review. External files, interpreters, script inputs, permissions and Apple event access must exist on the host. |
| Archives | Create ZIP archives and safely extract formats supported by the host's libarchive. | Unsafe paths, links and special files are rejected; unsupported/encrypted formats or missing codecs fail closed. Extraction is limited to 100,000 entries, 10 GiB and five minutes. ZIP creation and extraction have different supported format sets. |
| Upload | Reusable named servers in Settings for FTP, explicit/implicit FTPS, SFTP and WebDAV over HTTP(S), with read-only connection tests. Upload actions select a server and remote folder; passwords stay in Keychain, bound to protocol, host, port and user. | Exports omit connection details and server bindings; imported upload rules start disabled and require a saved server to be selected. TLS trust and SSH known-host checks remain enabled. FTP safe skip/rename and replacement of existing folders fail closed; SFTP without hard-link support can leave a partial remote file on failure; WebDAV folder replacement stages then moves, with server-dependent atomicity. Unverified Hazel upload encodings are blocked. |
| Control | Pause, Ignore, Continue Matching Rules and Run Rules on Folder Contents. | Continue and recurse require Hazel rule ordering. Rules and their actions execute only when enabled and supported; imported unsupported parts remain blocked. |

## Pattern formatting and resource limits

- Action patterns support literal text, names/extensions, rule attributes and captures, dates, typed Spotlight values, counters, comments, dynamic tags, and subfolder separators. Native Rename offers Basic and Attributes modes, and Move offers a Sort into Subfolder mode; changing modes preserves each draft. Defaults, numeric adjustment/digit padding/grouping, ordered text or regex replacements, case changes and Unicode-safe maximum length are editable. Text tokens can split into safe nested folders; empty, traversal or symlink components are rejected.
- Numeric and alphabetic per-folder counters support always-increment and lowest-available rename allocation. Native formatting does not imply that every Hazel counter or formatting archive encoding is understood. Unsupported encodings remain blocked.
- Text capture and custom-list matching are bounded to 1 MB of input/output and 10,000 matches; file-backed tables are bounded to 1 MB and 1,001 rows. Peer scans cover at most 10,000 entries and check a two-second budget; watcher rechecks yield between batches.
- Common text and PDF extraction is limited to 100 MiB; PDFs to 100 pages, PDF OCR to 20 pages, and image OCR to 25 MiB. OCR and Spotlight fallback have timeouts. Date Taken uses image EXIF or embedded creation metadata in local MOV/MP4/M4V videos up to 1 GB; video reads have a three-second wait and at most four concurrent requests. Missing or oversized media do not fall back to the current time.
- PDF passwords are saved in Forel-owned Keychain entries; the rule stores only a UUID reference. Export clears that reference and import requires a new password. Background reads do not prompt. Draft edits do not overwrite or remove an active credential, so unused Keychain entries can remain until a safe cleanup mechanism exists. Hazel password imports and unverified per-rule text-recognition options remain blocked.
- Hazel archive import limits input to 20 MiB, 100,000 archive objects, 128 levels and one million resolution nodes. Cyclic, truncated or invalid references are rejected. Unknown fields and unsupported settings are reported instead of silently broadening a rule.

## Testing and references

`scripts/test-hazel-corpus.py` verifies pinned revisions and hashes and requires its fixtures; `scripts/setup-hazel-corpus.py` can prepare them. The strict suite requires a validated debug-only `FOREL_TEST_TRASH_DIRECTORY` under `/tmp/forel-hazel-*`; it does not change HOME and rejects release configuration. Media, Finder, Spotlight, external apps and network services have host-specific behavior; fixture substitutions and dependency errors are identified in the runtime inventory.
